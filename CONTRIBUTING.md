# Contributing to Awesome PGlite

Thanks for helping keep this list useful. Quality and relevance matter more than its length.

## What belongs here

We include resources that actually use electric-sql/PGlite. Unrelated projects with the same name, server-only PostgreSQL tools, and speculative adapters are excluded.

- Link to the original repository, documentation, or author-maintained resource.
- Show direct use of this ecosystem. A claim in a marketing page alone is insufficient.
- Prefer a working example, documented package, or substantive guide over an empty starter or link roundup.
- Check that the resource is publicly accessible and has enough instructions or source to evaluate.
- Identify archived, obsolete, experimental, or version-specific work. An older example must offer a lesson that current material does not cover.
- Check the upstream license before recommending code reuse. This list's CC0 license does not relicense anything linked here.
- Disclose if you created the resource, work for its owner, or receive compensation from it.

## Adding a resource

1. Search the README for the URL and for equivalent coverage.
2. Choose the closest existing category. Propose a new category only when it has a distinct purpose.
3. Use this format, with a factual one-sentence description and the correct ownership label.

   ```markdown
   - [Resource name](https://example.com/resource) - What it helps someone do. **Community.**
   ```

4. Use **Official** for the ecosystem team's work, **Integration** for an integrating project's documentation or examples, and **Community** for other authors.
5. In the pull request, explain why the entry is useful, how you verified its relationship to the ecosystem, and any version or license constraints.
6. Add a dated row to `VERIFICATION.md` with the resource URL, evidence inspected, and your check result. Do not imply that a link check proves the app runs.

Use direct HTTPS links, sentence case, and short descriptions. Avoid affiliate links, tracking parameters, popularity claims, duplicate listings, and sales copy. Keep the table of contents in sync if headings change.

## Corrections and removals

Open a correction issue or pull request for a broken URL, misleading description, abandoned project, missing compatibility note, or duplicate. Include the evidence and a replacement URL when available. Maintainers may remove an entry when its usefulness or relevance can no longer be established.

## Before submitting

- Open the added or changed links and read the linked material.
- Review the GitHub Markdown preview and check the table of contents.
- Confirm that the description is original and supported by the source.
- Describe exactly what was checked and what remains untested.

By contributing original text, you agree to dedicate it under the repository's [CC0 1.0 license](LICENSE). All participation follows the [code of conduct](CODE_OF_CONDUCT.md).
